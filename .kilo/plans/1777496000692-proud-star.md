# Topbar & Sidebar Responsive Adjustments

## Summary

Three changes to the layout:
1. Header background matches page background (not sidebar), sidebar keeps its own distinct tone
2. Below 960px: sidebar hidden, but hamburger + logo remain in topbar; hamburger opens a full overlay sidebar
3. Below 600px: hide logo text too, keep only hamburger in topbar

## Files to Modify

1. **`dev/web/src/hooks/use-mobile.tsx`** — Change `MOBILE_BREAKPOINT` from 768 to 960
2. **`dev/web/src/layouts/MainLayout.tsx`** — Header bg, responsive logo/trigger visibility, restructure topbar for mobile
3. **`dev/web/src/components/ui/sidebar.tsx`** — No changes needed (mobile sheet behavior already handled by shadcn sidebar)

## Current Behavior

- `useIsMobile()` uses 768px breakpoint → sidebar switches to Sheet overlay below 768px
- Header has no background (`bg-transparent` effectively)
- `TopBarLogo` is a `fixed` element that follows the sidebar edge
- `SidebarTrigger` (hamburger) only lives inside the sidebar's `SidebarHeader`
- On mobile: no hamburger visible in the topbar (it's inside the hidden sidebar Sheet)

## Target Behavior

| Viewport | Sidebar | Topbar contents |
|----------|---------|----------------|
| ≥960px   | Visible, collapsed/expanded | Logo text + slogan (follows sidebar edge) |
| 600–959px | Hidden, opens as Sheet overlay on hamburger click | Hamburger + Logo text + slogan |
| <600px   | Hidden, opens as Sheet overlay on hamburger click | Hamburger only |

## Step-by-Step

### 1. Change mobile breakpoint to 960px

**File:** `dev/web/src/hooks/use-mobile.tsx`

```tsx
const MOBILE_BREAKPOINT = 960
```

This makes the sidebar component treat everything below 960px as "mobile" → sidebar becomes a Sheet overlay.

### 2. Restructure TopBarLogo to work at all breakpoints

**File:** `dev/web/src/layouts/MainLayout.tsx`

Replace the current `TopBarLogo` component. It needs to:
- On desktop (≥960px): stay `fixed` position, following sidebar edge (current behavior)
- On tablet (600–959px): display inline in the topbar (sidebar is hidden, so no sidebar edge to follow)
- On mobile (<600px): hidden entirely

New approach — make `TopBarLogo` not fixed-position but inline, with responsive positioning:

```tsx
function TopBarLogo() {
  const { state } = useSidebar();
  return (
    <Link
      to="/"
      aria-label="JCP Home"
      className="flex flex-col rounded-md px-2 py-1 hover:bg-stone-100 dark:hover:bg-stone-800/60 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-stone-500 transition-[margin-left] duration-200 ease-linear max-[600px]:hidden"
      style={{
        marginLeft:
          state === "collapsed"
            ? "var(--sidebar-width-icon)"
            : "var(--sidebar-width)",
      }}
    >
      <span className="text-lg font-bold tracking-tight leading-tight text-stone-800 dark:text-stone-200">
        jcp<span className="text-accent-primary">.</span>haven
      </span>
      <span className="text-[10px] font-medium leading-tight text-stone-400 dark:text-stone-500 italic">
        Bits, Beats, and Being
      </span>
    </Link>
  );
}
```

Key changes:
- Removed `fixed` positioning → now uses `marginLeft` based on sidebar width to offset from the left
- Added `max-[600px]:hidden` to hide logo on small screens
- Removed `hidden sm:inline` from slogan — it's always visible alongside the name (both hide together at <600px)

### 3. Add hamburger trigger to the topbar for mobile

**File:** `dev/web/src/layouts/MainLayout.tsx`

The hamburger needs to appear in the topbar on screens <960px. Add a `SidebarTrigger` directly in the header:

```tsx
<header className="sticky top-0 z-10 flex h-14 shrink-0 items-center gap-2 px-3 bg-[#faf9f8] dark:bg-[#0a0a0a]">
  <SidebarTrigger className="md:hidden h-8 w-8 ..." />
  <TopBarLogo />
  <div className="flex-1" />
</header>
```

Wait — the current breakpoint class `md:hidden` maps to 768px (Tailwind default). But we changed `MOBILE_BREAKPOINT` to 960. We need a custom breakpoint or use `max-[960px]:flex / max-[960px]:hidden`.

Better approach: use `@media (max-width: 959px)` via Tailwind's arbitrary values:

```tsx
<SidebarTrigger className="max-[960px]:flex hidden h-8 w-8 ..." />
```

Actually, `SidebarTrigger` is a `<Button>` which is `inline-flex` by default. So:

```tsx
<SidebarTrigger className="[&]:max-[960px]:flex max-[960px]:flex hidden h-8 w-8 ..." />
```

Hmm, this gets tricky with Tailwind arbitrary variants. Simpler approach: wrap in a div:

```tsx
<div className="hidden max-[960px]:block">
  <SidebarTrigger className="h-8 w-8 ..." />
</div>
```

### 4. Set header background to page background color

**File:** `dev/web/src/layouts/MainLayout.tsx`

The page background is `#faf9f8` (light) / `#0a0a0a` (dark). These are already defined in `index.css` on `body`. The cleanest approach is to use the shadcn `bg-background` token:

```tsx
<header className="sticky top-0 z-10 flex h-14 shrink-0 items-center gap-2 px-3 bg-background">
```

`--background` is defined as `30 15% 98%` (light) / `0 0% 4%` (dark) in the CSS, which maps to the page background colors.

### 5. Hide the sidebar hamburger trigger from inside the sidebar on mobile

The `SidebarHeader` trigger should only show on desktop (≥960px). On mobile, the sidebar is a Sheet anyway and the trigger in the topbar handles toggling.

```tsx
<SidebarHeader className="hidden max-[960px]:hidden px-2 pt-2 pb-0">
```

Wait, it should show on desktop. The sidebar is always visible on desktop, so:

```tsx
<SidebarHeader className="px-2 pt-2 pb-0 max-[960px]:hidden">
```

Actually on mobile the sidebar becomes a Sheet. The `SidebarHeader` is inside the Sheet content. We might want to keep the trigger there too for the mobile sheet. Let me reconsider...

On mobile (<960px): sidebar is a Sheet overlay. The user clicks the topbar hamburger → Sheet opens → they see the nav links. No need for a hamburger inside the Sheet itself (there's already an X close button via Sheet). So hiding the SidebarHeader trigger on mobile is fine.

But wait — in the shadcn sidebar, on mobile the trigger inside the Sheet would look weird. Let's keep it visible in both places — it's a minor UX thing. Actually, the user said "hamburger opens and totally hide sidebar" on mobile, which is the default Sheet behavior. The hamburger inside the Sheet would just close it, which is fine.

Let's keep the sidebar header trigger always visible (no change needed) and also add one in the topbar for mobile.

### 6. Update TopBarLogo left positioning for mobile

On mobile (<960px), the sidebar is hidden (no gap). The logo should start from the left edge:

```tsx
function TopBarLogo() {
  const { state } = useSidebar();
  return (
    <Link
      to="/"
      aria-label="JCP Home"
      className="flex flex-col rounded-md px-2 py-1 hover:bg-stone-100 dark:hover:bg-stone-800/60 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-stone-500 transition-[margin-left] duration-200 ease-linear max-[600px]:hidden"
      style={{
        marginLeft:
          window.innerWidth < 960
            ? 0
            : state === "collapsed"
              ? ...sidebar icon width
              : ...sidebar width
      }}
    >
```

Using `window.innerWidth` is not reactive. Better: use the `isMobile` from the sidebar context:

```tsx
function TopBarLogo() {
  const { state, isMobile } = useSidebar();
  return (
    <Link
      to="/"
      ...
      style={{
        marginLeft: isMobile
          ? 0
          : state === "collapsed"
            ? "var(--sidebar-width-icon)"
            : "var(--sidebar-width)",
      }}
    >
```

This is clean and reactive via the sidebar context.

### 7. Hamburger visibility in sidebar header

On mobile the sidebar is a Sheet. The trigger inside the Sheet header is redundant (Sheet has its own close). But it's not harmful. Let's hide it on mobile to keep the Sheet clean:

```tsx
<SidebarHeader className="px-2 pt-2 pb-0 max-[960px]:hidden">
```

Wait, but `max-[960px]` in Tailwind corresponds to `@media (max-width: 960px)`. The sidebar mobile detection also uses 960px now. When the sidebar renders as a Sheet on mobile, `max-[960px]:hidden` would hide the header. But the header is inside the Sheet content — it should probably still show the nav links header area, just without the hamburger.

Actually, simplest approach: just leave the SidebarHeader as-is. The hamburger inside the mobile Sheet is fine — it just closes the Sheet. No special handling needed.
