# Plan: Add dedicated `projectsPage` Sanity type for Projects page

## Goal
Create a new `projectsPage` document type in Sanity Studio so the projects page has editable eyebrow, hero title/subtitle, and body content — similar to how other pages use the generic `page` type, but as a dedicated type that can also reference showcase projects.

## Files to Modify

### 1. New file: `dev/sanity/schemaTypes/projectsPageType.ts`
Create a new Sanity document type `projectsPage` with fields:
- `title` (string, required)
- `slug` (slug, required, source from title)
- `eyebrow` (string)
- `subtitle` (string)
- `body` (Portable Text array of blocks)
- `seoTitle` (string)
- `seoDescription` (text)

Follow the same pattern as `showcaseProjectType.ts` and `pageType.ts` — use `defineType`, `defineField`, `defineArrayMember`.

### 2. Edit: `dev/sanity/schemaTypes/index.ts`
Register the new `projectsPageType` — add import and push to `schemaTypes` array.

### 3. Edit: `dev/web/src/lib/cms/types.ts`
Add a `SanityProjectsPage` raw response type (mirroring `SanityPage` structure) and a `ProjectsPageData` transformed type with `bodyPlainText`.

### 4. Edit: `dev/web/src/lib/cms/queries.ts`
Add a new `projectsPageQuery` GROQ query targeting `_type == "projectsPage"`:
```groq
*[_type == "projectsPage"][0]{
  title,
  "slug": slug.current,
  "subtitle": coalesce(subtitle, seoTitle),
  "eyebrow": coalesce(eyebrow, seoDescription),
  body
}
```

### 5. Edit: `dev/web/src/lib/cms/api.ts`
- Add `getProjectsPage()` function following the `getPageBySlug` pattern
- Import new query and types
- Return `ProjectsPageData` with `bodyPlainText` extracted via `toPlainText()`

### 6. New file: `dev/web/src/lib/cms/useCmsProjectsPage.ts`
Create a hook `useCmsProjectsPage()` following the `useCmsPage` pattern but:
- Calls `getProjectsPage()` from api.ts (no slug param — there's only one projects page document)
- Accepts a fallback `ProjectsPageData` object
- Returns `{ page, isLoading, error }`

### 7. Edit: `dev/web/src/pages/ProjectsPage.tsx`
Replace `useCmsPage("projects", ...)` with `useCmsProjectsPage()`:
- Import the new hook
- Update the fallback data to include an eyebrow value (e.g. `"Portfolio"`)
- The rest of the page (showcase projects grid via `useCmsProjects`) stays unchanged

## Discoveries
- The music page uses the generic `page` type fetched by slug — no dedicated schema. This plan creates a more robust dedicated type for projects.
- `useCmsProjects` (fetching `showcaseProject` documents) remains separate and untouched — it feeds the project cards grid.
- The new type queries `*[_type == "projectsPage"][0]` (first document) rather than by slug, since there will only ever be one projects page. This is simpler than slug-based lookup.
- All GROQ field patterns (`coalesce`, block arrays) follow existing conventions from `pageBySlugQuery`.

## Implementation Order
1. `projectsPageType.ts` (Sanity schema)
2. `schemaTypes/index.ts` (register schema)
3. `types.ts` (add TS types)
4. `queries.ts` (add GROQ query)
5. `api.ts` (add fetch function)
6. `useCmsProjectsPage.ts` (add React hook)
7. `ProjectsPage.tsx` (wire it up)
