# Plan: Remove Muted Text Colors from All `prose` Containers

## Context

The home page hero section was just fixed to remove `text-stone-600` from its `prose` container. The same issue exists on three other pages that render CMS rich text content inside `prose` wrappers. `prose` provides its own optimal text color, and overriding it with `text-stone-600` or `text-stone-800` fights against the typography plugin's defaults.

## Changes

### 1. `dev/web/src/pages/BlogListPage.tsx` (line 41)

```diff
- richTextClassName="prose prose-stone text-stone-600 dark:prose-invert"
+ richTextClassName="prose prose-stone dark:prose-invert"
```

### 2. `dev/web/src/pages/BlogPostPage.tsx` (line 56)

```diff
- className="prose prose-stone text-stone-800 dark:prose-invert"
+ className="prose prose-stone dark:prose-invert"
```

### 3. `dev/web/src/pages/MusicPage.tsx` (line 63)

```diff
- richTextClassName="prose prose-stone text-stone-600 dark:prose-invert"
+ richTextClassName="prose prose-stone dark:prose-invert"
```

## Summary

## Notes

- No changes needed for the home page blog/music/projects sections — they render structured card data (titles, excerpts, tags), not free-form CMS rich text. `prose` is not applicable.
- `AboutPage.tsx` and `ProjectsPage.tsx` do not render `page.body` (Portable Text) at all, so they have no `prose` usage to fix.
